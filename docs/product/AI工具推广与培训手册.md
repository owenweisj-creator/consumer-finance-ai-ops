# AI 工具推广与培训手册

## 1. 培训目标

让经营分析、风险和业务人员在一小时内做到：

1. 会用自然语言问一个经营指标问题。
2. 能判断 AI 返回的 SQL 和数字是否可信。
3. 知道哪些问题不能问、哪些结论必须人工复核。
4. 能把每周重复的取数需求转成固定模板或知识库条目。

## 2. 60 分钟培训大纲

| 时间 | 内容 | 形式 |
|---|---|---|
| 10 分钟 | 为什么做 AI Copilot：取数慢、口径散、AI 不可信 | 业务案例 |
| 20 分钟 | 3 个真实场景演示：月报、渠道对比、异常归因 | 现场演示 |
| 10 分钟 | 错误案例：模型用了错误分母，结果差 8 个百分点 | 复盘 |
| 10 分钟 | 安全边界与人工复核清单 | 讲解 + 问答 |
| 10 分钟 | 现场练习：每人提 1 个问题，现场验证 | 实操 |

## 3. 三个演示场景

### 场景 A：周会前查指标

问题：最近 6 个月每月的审批通过率和用信率是多少？

看点：

- 通过率是否按“审批通过量 / 进件量”重算。
- 用信率是否按“Approved /（Approved + Unused offer）”重算。
- 是否明确时间范围和金额单位。

### 场景 B：渠道对比

问题：最近一个月各渠道的审批金额和通过率是多少？

看点：

- 是否按渠道重新汇总，而不是对月度比率求平均。
- 是否区分“金额高”与“通过率高”，避免把规模和质量混为一谈。

### 场景 C：异常归因

问题：最近一个月审批通过率变化中，哪个渠道的结构效应最大？

看点：

- 是否使用结构效应/比率效应分解。
- 是否能解释“结构效应”和“比率效应”的业务含义。

## 4. 错误案例

模型曾生成：

```sql
SELECT avg(approval_rate) FROM mart.v_funnel_monthly
```

问题：不同渠道的进件量不同，直接对比率求平均会让小渠道和大渠道权重相同，结果失真。

正确做法：

```sql
SELECT sum(approved) / sum(applications) FROM mart.v_funnel_monthly
```

培训时要强调：**比率永远回到分子和分母**。

## 5. 安全边界

- 只能查语义层中的 `mart.v_*` 视图。
- 只能执行 `SELECT`，禁止写操作和多语句。
- 结果最多 200 行，不输出客户级敏感信息。
- 报告数字必须能追溯到 SQL 或 Python 计算结果。
- AI 输出是辅助决策，不是最终结论。

## 6. 人工复核清单

- 分母是否与指标口径一致？
- 时间范围是否明确？
- 比率是否重新汇总？
- 异常是否有业务事件解释？
- 结论是否区分相关与因果？
- 是否说明了数据局限？

## 7. 推广与采纳指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 激活率 | 目标用户中至少使用 1 次的比例 | ≥ 60% |
| 周活 | 每周至少使用 1 次的用户数 | 持续 4 周 |
| 人均问数 | 总问数 / 活跃用户 | ≥ 3 次/周 |
| 报告节省时间 | 手工耗时 - 工具耗时 | ≥ 60% |
| 口径争议次数 | 因口径不一致产生的返工次数 | 下降 |
| 失败问题闭环率 | 进入 backlog 并完成修复的比例 | ≥ 80% |

## 8. 常见问题

**Q：AI 说的数字和我 Excel 里的不一样，信谁？**  
A：先核对口径和分母，再看时间范围。以数据仓库的 SQL 结果为准，Excel 只作为对照。

**Q：能不能直接连生产库？**  
A：当前只连只读数据仓库，且只能查语义层视图。生产库需要单独审批、脱敏和审计。

**Q：AI 能不能直接给授信结论？**  
A：不能。AI 只做辅助分析和建议，授信决策必须由有权限的人按制度完成。

**Q：模型答错了怎么办？**  
A：记录问题、SQL、错误原因，进入评测集和 backlog；同类问题修复后重跑评测。
