# S1 数据与业务建模：带教笔记

## 一、这个阶段解决什么业务问题

经营分析不是先画图，而是先回答三个问题：

1. 一笔贷款从申请到逾期，经历了哪些状态？
2. 每个状态用什么指标衡量，分子和分母分别是什么？
3. 哪些字段能支撑这些指标，哪些字段只是“看起来有用”？

如果这三个问题没答清楚，后面的 SQL、看板、AI 问数都会变成“有数字但没有业务含义”。

## 二、消费金融的业务链路

```text
获客 → 申请 → 审批 → 用信/放款 → 还款 → 逾期 → 催收/核销 → 复贷
```

对应到数据：

- `previous_application`：历史申请与审批结果，能还原“申请—审批—用信”漏斗。
- `application_train`：当前申请/在贷客户快照，带 `TARGET` 风险标签。
- `installments_payments`：每期应还、实还、逾期天数，能还原还款行为。
- `POS_CASH_balance` / `credit_card_balance`：月度账本，能看账龄和额度使用。
- `bureau` / `bureau_balance`：外部征信与历史信用表现。

## 三、核心指标口径

### 审批通过率

公式：（Approved + Unused offer）/ 全部申请。

为什么把 Unused offer 算通过？因为它是“公司批了、客户没用”，属于用信环节的流失，不属于审批拒绝。把两者混在一起，会低估审批通过率、也无法单独分析“批而不用”。

### 用信率

公式：Approved /（Approved + Unused offer）。

它回答的是：批出去的额度，有多少真的被用了。用信率低可能是额度不够、定价太高、触达不够，也可能是客户本来就在比价。

### 不良率

公式：TARGET=1 的客户数 / 客户总数。

注意：`TARGET` 是 30+ 天逾期标签，不是核销率，也不是最终损失率。面试时如果把它说成“坏账率”，会被追问口径。

### Vintage

按放款月份分 cohort，再看每个账龄月的逾期率。它的价值是控制“账龄结构变化”：如果这个月新客多、老客少，整体逾期率可能自然下降，但不代表风控变好。

## 四、星型模型怎么建

- 维度：客户、产品、渠道、地区、日期。
- 事实：申请、历史申请、分期还款、POS 月度账本、信用卡月度账本、征信。
- 粒度：
  - `fact_previous_application`：一笔历史申请一行。
  - `fact_installment`：一笔历史申请的每一期还款一行。
  - `fact_pos_monthly` / `fact_credit_card_monthly`：一笔合同一个月一行。

为什么不用一张大宽表？因为申请、还款、月度账本的粒度不同。强行 join 会让金额和笔数重复计算，这是经营分析最常见的错误之一。

## 五、数据质量要检查什么

1. 主键是否唯一：`SK_ID_PREV`、`SK_ID_BUREAU`。
2. 关键字段缺失率：`AMT_CREDIT`、`AMT_ANNUITY`、`NAME_CONTRACT_STATUS`、`DAYS_ENTRY_PAYMENT`。
3. 枚举值是否稳定：审批状态、合同类型、渠道。
4. 日期映射是否合理：`DAYS_DECISION` 映射后是否落在预期区间。
5. 金额和比率的极端值是否会影响平均值。
