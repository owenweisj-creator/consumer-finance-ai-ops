# JD 覆盖矩阵

> 目标岗位：经营分析管培生-AI 方向。逐条对照 JD 中的 AI 相关内容，给出项目证据与面试话术。

| JD 要求 | 项目证据 | 面试怎么讲 |
|---|---|---|
| 经营数据监测与分析体系 | `mart.v_kpi_monthly`、HTML 看板、Excel 工作簿 | 先定义指标树，再建星型模型，最后做看板；不看单点数字，先看趋势和结构 |
| 周报/月报/专项分析 | `outputs/reports/` 下三类报告 | 周报看环比和行动项，月报看结构和风险，专项做归因分解 |
| 识别经营异常、预警和建议 | 稳健 z 分数异常检测、异常清单 | 用滚动中位数和 MAD 避免极端值干扰；异常必须配业务事件复核 |
| 业务诊断与决策支持 | 量–价–险三角、结构/比率分解 | 通过率下降先拆渠道结构，再看同一渠道自身变化 |
| 经营效率提升 | 报告自动化、指标口径字典、UAT | 把重复取数和手工核对变成脚本与模板，报告生成 < 1 分钟 |
| AI 研发内部对接与推动 | PRD、需求池、RACI、里程碑、UAT | 先收需求再做原型，按里程碑验收，不让 AI 项目变成 demo |
| 需求收集、进度追踪、问题协调、验收测试 | `docs/product/PRD`、GitHub Issues、UAT | 每个需求有验收标准；每个问题有负责人和截止日 |
| AI 工具推广与培训 | 培训手册、AI 使用手册、知识库 | 培训不只讲功能，要讲错误案例和安全边界 |
| 沉淀 AI 最佳实践与内部知识库 | `knowledge/`、Prompt 版本、协作日志 | 口径、模板、失败案例都入库，减少重复踩坑 |
| 跟踪 AI 行业动态与应用案例 | AI 行业简报、3 个创新提案 | 不做“新闻搬运”，要落到消费金融场景和可验证指标 |
| AI 应用创新建议与产品策划 | 经营例会助手、审批策略 Copilot、客户经营 Agent | 从用户痛点出发，先写 PRD 和验收，再谈模型 |
| 真正用过 AI，能说出工具和问题 | DeepSeek、Codex、NL2SQL、RAG、评测 | 讲一个“AI 给了错误 SQL，我怎么发现并修正”的具体案例 |
| 把 AI 当队友，会提问、迭代、验证 | 协作日志、Prompt v1/v2、40+ 题评测 | 我负责定义问题、给约束、验收；AI 负责加速实现 |
| Prompt 工程经验 | `prompts/nl2sql_v1.md`、`v2.md`、变更记录 | v2 增加“先拆指标/时间/维度/过滤”、少样本和拒答规则，准确率提升 X |
| AI 工作流搭建 | FastAPI + 语义层 + NL2SQL + RAG + 报告 Agent | 工作流不是把模型接上就完了，要有校验、回退和人工复核 |
| AI 实际项目经验 | 本项目端到端 | 从数据、分析、AI 到产品化和简历，完整闭环 |
| 对 AI 行业有真实热情 | 行业简报、创新提案、持续评测 | 我能说清哪些场景适合 LLM，哪些不适合 |
| 跨部门协同 | RACI、会议纪要模板、行动项追踪 | 用机制减少信息不对称：周会、看板、行动项、复盘 |
| Excel / SQL / Python | DuckDB SQL、Pandas、Excel 工作簿 | 工具只是手段，关键是能把业务问题翻译成数据问题 |
| 数据敏感度，能从数据发现问题 | 5 条经营洞察、异常清单 | 先看分母，再看结构，最后看单客群；不把相关当因果 |
